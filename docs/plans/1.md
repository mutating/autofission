# Autofission initial release plan

## Goal

Turn the cluster-local Fission capacity scaler into a reusable typed Python package, CLI, OCI image, and Helm installation without carrying fixed node addresses or cluster-specific dependencies.

## Behavioural contract

- Manage only explicitly labeled `newdeploy` Functions.
- Derive the HPA ceiling from free per-node scheduler requests rather than aggregate allocatable capacity.
- Never patch from a stale Function snapshot.
- Preserve unrelated Function fields and annotations.
- Degrade readiness on any incomplete cycle and retry safely.
- Run as one self-healing, non-HA controller instance.

## Test-first milestones

1. Specify the complete accepted Quantity corpus, scheduler rounding, int64 bounds, and hostile inputs.
2. Specify Pod request accounting for regular containers, classic and restartable init containers, Pod-level resources, overhead, terminal Pods, and own Function Pods.
3. Specify heterogeneous node bin-packing, occupied resources, Pod slots, taints, cordons, deletion, and malformed API objects.
4. Specify Environment inheritance, partial and zero Function overrides, fetcher overhead, `MinScale`, `MaxScale` int32 clamping, and idempotent patches.
5. Specify pagination, `410` restart, token cycles, page bounds, retries, kubeconfig/in-cluster selection, and least-privilege RBAC.
6. Specify CLI precedence, one-shot and daemon exit semantics, cooperative signals, stale health reset, and installed entry points.
7. Build wheel/sdist/container/chart smoke tests and require 100% line plus branch coverage.

## Release gate

Ruff, formatting, strict mypy, all tests, 100% line/branch coverage, isolated wheel install, `twine check --strict`, Helm lint/render validation, version consistency, and a clean `develop` worktree diff ready for the maintainer to commit.
